# Deployment checklist (one-time, manual)

Pairs with `render.yaml` and `.github/workflows/web.yml`. Work top to bottom.
Stack: Neon (Postgres) · Cloudflare R2 (media) · Render (API) · Cloudflare Workers (admin) · Netlify (site).

## Neon (database)

- [ ] Create a project (region **AWS ap-southeast-1 / Singapore**, next to Render), Postgres 18, database `qdjr`.
- [ ] Dashboard → Connect → copy two connection strings, both with `?sslmode=require`:
      - **Pooled** (host contains `-pooler`) → Render `DATABASE_URL`
      - **Direct** (no `-pooler`) → Render `MIGRATIONS_DATABASE_URL`
- [ ] Nothing else: the API applies every migration (0001–0009) on its first start.

## Cloudflare R2 (media)

- [ ] R2 → Create bucket `qdjr-media` (R2 needs a payment method on file; the free tier covers this site).
- [ ] Bucket → Settings → Public access → **Allow r2.dev subdomain**. Note the `https://pub-<hash>.r2.dev` URL → Render `MEDIA_PUBLIC_BASE_URL`.
      (Cloudflare rate-limits r2.dev; move to a custom domain such as `media.qdjr.dev` once the qdjr.dev zone is on Cloudflare — only `MEDIA_PUBLIC_BASE_URL` changes, stored rows don't.)
- [ ] R2 → Manage API tokens → Create token, **Object Read & Write**, scoped to `qdjr-media` → note Access Key ID + Secret. Account ID is on the R2 overview page.

## Render (API)

- [ ] Dashboard → New → Blueprint → connect `quocdaijr/qdjr-admin`, branch `main`; it reads `render.yaml`.
- [ ] Enter when prompted: `DATABASE_URL`, `MIGRATIONS_DATABASE_URL`, `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `MEDIA_PUBLIC_BASE_URL`, `BOOTSTRAP_ADMIN_EMAIL`, `BOOTSTRAP_ADMIN_PASSWORD` (≥ 10 chars). `JWT_SECRET` is generated by Render.
- [ ] First deploy green; Logs show `migrations applied`, `bootstrap admin created`, `media storage: r2`. Then `curl https://qdjr-admin-api.onrender.com/healthz`.
- [ ] Sign in to the admin once and change the bootstrap password (user menu → Change password). Optionally clear `BOOTSTRAP_ADMIN_PASSWORD` in Render afterwards; it is ignored once the account exists.
- [ ] Settings → Custom Domains → add `api.qdjr.dev`; then add the CNAME at Netlify DNS (see `infra/dns/README.md`).

## Cloudflare Workers (admin)

- [ ] My Profile → API Tokens → Create → template "Edit Cloudflare Workers"; copy the token and the Account ID.
- [ ] GitHub secrets: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`.
- [ ] GitHub variable: `NEXT_PUBLIC_API_URL=https://api.qdjr.dev`.
- [ ] Push to `main` → `web.yml` deploy job prints `https://qdjr-admin.<account>.workers.dev`.
- [ ] Append that origin to `CORS_ORIGINS` in `render.yaml`, push (Render re-syncs).

## Netlify (site)

The public site stays in its own repo, `quocdaijr/qdjr`, on its existing Netlify site; it reads the API since quocdaijr/qdjr#29.

- [ ] Optional: Environment variables `APP_URL=https://qdjr.dev`, `API_URL=https://api.qdjr.dev` (the code defaults to both).
- [ ] Deploy previews run on `*.netlify.app` origins the API does not allow, so client-side navigation and search fail there; production is fine.

## Done when

- [ ] `curl https://api.qdjr.dev/v1/posts | jq '.meta.total'` → `2`
- [ ] admin login at the workers.dev URL shows the `super_admin` badge; `/admin/profile` shows the seeded JSON
- [ ] an image uploaded in `/admin/media` loads from the r2.dev URL
- [ ] `https://qdjr.dev/about` renders; editing the JSON in the admin and reloading `/about` shows the change
